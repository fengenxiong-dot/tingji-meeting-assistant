# 听记君 · Windows 电脑端第一版

使用电脑麦克风录制会议或访谈，通过 OpenRouter 分段转写，并使用独立的语言模型生成总结、检索历史档案。旧版百炼 WebSocket 配置仍兼容。

## OpenRouter 模式（当前默认）

- 转写、总结的基础地址均填写 `https://openrouter.ai/api/v1`。
- 转写模型默认 `qwen/qwen3-asr-0.6b`。
- 总结及问答模型默认 `~deepseek/deepseek-pro-latest`，保留开头的 `~`。
- 在两处 Key 输入框中填写 OpenRouter Key，可使用同一个 Key。
- 转写调用 `/audio/transcriptions`，发送 base64 WAV，约每8秒提交一个连续音频段。停止录音时提交不足8秒的尾段。出字延迟包括采集8秒及模型处理、排队时间，**不是逐字 WebSocket 实时识别**。
- 本版使用标准 JSON 文字结果，来源时间定位到音频段，尚未启用提供商可选的字级时间戳。
- 每段成功后持久保存已处理位置，包括无文字的成功结果；失败重试同一段，补转写从成功位置继续。停止服务时中止未完成的请求，不把它计为成功。
- 本地录音和每10分钟总结的行为保留。转写速度落后时，阶段总结只能覆盖已返回的文字，最终总结等待尾段处理完成。
- 当前验证使用模拟 STT 服务；真实模型权限、额度、响应速度及长时间录音仍需试录确认。

参考：[OpenRouter STT 官方文档](https://openrouter.ai/docs/guides/overview/multimodal/stt)。

**当前形态：Windows 桌面便携版 + 可选浏览器界面。** 手机连接、录音笔导入、说话人区分和电脑内部音频采集不在本版范围。

## 听记场景与暂停

- 录音开始前在“声音来源”旁选择“会议场景”或“面试场景”，默认会议场景。旧记录按会议场景处理。
- 会议场景继续使用会议摘要、关键结论、待办事项、待确认问题结构。面试场景只输出“核心问答记录”和“初步评价”，初步评价仅围绕候选人的基础素质与能力做辅助观察，不做是否通过或录用判断。
- 面试记录生成总结后，可在记录详情中点击“导出 Word”保存为 `.docx` 文件。Word 文档包含记录标题、基本信息、核心问答记录和初步评价，不包含完整转写原文。
- 录音中可点击“暂停录音”，麦克风会释放；点击“继续录音”后仍写入同一条记录、同一个 WAV 和同一套总结，不会新建档案。
- 暂停期间不计入录音时长，也不推进 10 分钟总结周期。原文中会保留“已暂停 / 已继续”的时间标记。
- 暂停期间关闭页面或退出程序按录音中断处理，不支持跨重启继续同一场录音。

## 启动

1. 安装 Node.js 24 或更高版本（当前开发电脑已安装）。
2. 双击项目中的 `start.cmd`。首次运行会安装依赖。
3. 在 Microsoft Edge 或 Chrome 打开 <http://127.0.0.1:4317>。
4. 保持启动窗口和录音页面运行。结束录音后，等待存档和总结完成。

也可在项目目录运行：

```powershell
npm.cmd ci
npm.cmd start
```

如果提示端口被占用，先检查是否已经启动。不要同时启动两份服务。

## 模型设置

密钥请直接填入软件的“模型与设置”，无需发给开发助手。

### 语音转写（可选的百炼 WebSocket 模式）

- 百炼模型：`qwen-audio-3.0-asr-flash-streaming`。
- 使用 `run-task / finish-task` 的 inference WebSocket 协议，16kHz、16位、单声道 PCM。
- 百炼地址：`wss://dashscope.aliyuncs.com/api-ws/v1/inference`。
- 以你的百炼控制台为准填写对应地域的完整地址。如果使用业务空间专属地址，填写 `wss://实际WorkspaceId.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference`。
- 本版本不支持 `qwen3-asr-flash-realtime` 的另一套 realtime 事件协议。

### 总结及跨记录问答

- 默认使用上方 OpenRouter 配置；也可使用 `qwen-plus` 等兼容模型。
- 百炼基础地址示例：`https://dashscope.aliyuncs.com/compatible-mode/v1`。
- 以服务商控制台地址为准，基础地址不包含 `/chat/completions`。
- 接口须支持 Chat Completions；检索关键词扩展使用 JSON object 输出，扩展失败会降级为本地关键词检索。
- 语音与语言模型密钥单独填写，即使使用同一个百炼账号也需要填两处。
- “测试已保存的语言模型”会真实调用模型，可能产生少量费用。

API Key 使用 Windows DPAPI 的当前用户范围加密后写入数据库。浏览器读取设置只获得是否已配置，不会获得保存的密钥。也支持开发环境变量 `DASHSCOPE_API_KEY`、`LLM_API_KEY`；数据库内已保存的密钥优先。

官方接口参考（2026-09-15 核对）：

- [千问实时语音识别](https://help.aliyun.com/zh/model-studio/real-time-speech-recognition-user-guide)
- [流式转写客户端事件](https://help.aliyun.com/en/model-studio/fun-asr-client-events)
- [语言模型兼容接口](https://help.aliyun.com/en/model-studio/qwen-api-via-openai-chat-completions)

## 录音与存档

1. 新建记录，无需填写标题。累计足够转写文字后自动提炼标题，录音结束后再次更新；手动改名后不再覆盖。
2. 可通过声音来源旁的刷新按钮授权并列出麦克风；不刷新也可使用默认设备。
3. 点击“开始录音”，在浏览器允许麦克风。
4. 音频持续保存；转写区区分暂时结果和已确认的句子。
5. 每累计录制 10 分钟，生成一次截至当前已转写内容的总结。已有任务运行时不重复生成；结束后的最终总结会排队执行。
6. 点击“结束并存档”。转写队列落后时，处理会继续一段时间。
7. 补充参与人后点击“保存信息”。可导出 Markdown，包含总结及带时间位置的转写文字。

没有配置转写密钥仍可录音，记录会明确标记“转写待补全”。配置密钥后可用“补转写”，从最后一个确认句子的结尾继续处理。补转写不是极速离线转写，耗时接近剩余音频时长。

总结包含“会议摘要、关键结论、待办事项、待确认问题”。人工编辑并保存后，该版本保持在编辑区；新的自动总结进入历史版本，不覆盖人工版本。可将任一历史总结载入编辑区后再次保存。

转写文字修改后，离开该文字框即保存，原始识别文字也保留在数据库。修改不会自动重算已有总结，必要时点击“立即更新”。

## 跨记录助手

- 全部记录页支持标题、项目、标签/参与人及原文精确包含搜索、起止日期筛选。
- 档案助手通过本地中文双字词/英文关键词检索，优先获取原文；无匹配时才调用语言模型扩展关键词，选择原文片段供语言模型归纳。
- 候选片段包含相邻句，且在不同会议间轮流选取，降低长会议占满上下文的问题。
- 支持识别“三月”“2024年二月”“上个月”“最近一个月”等时间表达；明确选择的日期优先。“最近一个月”按最近 30 天处理，未指定年份的月份取最近一次该月份。结果显示实际日期范围，方便核对。
- 回答必须带有效 `[S1]` 等来源；不存在的引用会使该次回答被拒绝。来源卡片显示实际原文，点击可打开记录、定位句子和播放录音。
- 每次最多发送 60 个候选片段、约 24,000 个原文字符。超出时明确提示范围限制。当前未实现向量语义检索或对全部档案逐一穷尽审阅，不能把“没有检索到”等同于“不存在”。
- 问答输入是每次独立问题，当前不保存问答历史或将前一问自动作为上下文。

## 数据位置与恢复

```text
data/
  archive.sqlite       记录、原文、编辑、总结版本、加密模型配置
  archive.sqlite-wal   运行时数据库日志
  archive.sqlite-shm   运行时数据库共享文件
  audio/<记录编号>.wav  单声道原始采集音频
```

数据默认在项目目录内，界面显示最终实际路径。本机有目录映射时，显示路径可能比启动目录多一级，这两个路径可以指向同一目录。

- 一小时 PCM WAV 约 115 MB，90 分钟约 173 MB。
- 备份前停止录音、退出服务，然后复制整个 `data` 目录。
- 迁移到其他 Windows 用户或电脑后，录音及文字可以读取，DPAPI 密钥需要重新配置。
- 重启时修复未正常关闭的 WAV 文件头，把进行中的记录标为“录音中断”。这只能恢复已经收到的数据，不能恢复麦克风尚未发送的音频。
- 转写连接失败会退避重试，从已确认句子后补传；连续多次失败后暂停转写，但继续保存录音。
- 电脑麦克风超过 20 秒没有传来数据时，停止并保存记录，明确标记中断。
- 不支持电脑睡眠时继续录音。浏览器关闭、设备断开或音频系统暂停会停止采集；请在正式会议前用真实设备验证。

## 实际使用前的验收建议

1. 配置模型，测试语言模型连接。
2. 录制一段 1–2 分钟的测试音频，检查中文、数字、专业词和尾句，并回放确认。
3. 录制超过 10 分钟，检查阶段总结；手动编辑总结，再等待自动更新，确认人工版本仍在。
4. 建立两条内容有关联的记录，测试报价、结论变化、日期筛选和来源跳转。
5. 用一次 90 分钟测试核对音频长度、尾句、总结和异常提示，再用于重要会议。

## 多服务商版

发送其他电脑请使用 `dist/providers/听记君-多服务商版.exe`。本机的 `启动桌面版.cmd` 优先启动新版；启动前退出旧版桌面程序及旧网页服务。

“模型与设置”中语言模型服务商可选 DeepSeek、Kimi、智谱、千问、OpenRouter、自定义兼容接口。选择后自动填写基础地址和建议模型，模型输入框提供候选，也允许直接输入平台支持的其他 ID。API Key 必须来自对应服务商；切换地址不能沿用旧地址的密钥。同一地址留空保留已保存密钥。建议模型列表不是账号权限列表，具体可用性以平台为准。

语音转写独立选择 OpenRouter 分段转写或百炼 inference 流式转写，语言模型不能直接作为转写模型。百炼及 Kimi 的地域地址允许手动修改。

快速模式按服务商适配：DeepSeek、智谱及 Kimi K2.6 关闭可选思考；Kimi K3 降低推理强度，K2.7 Code 不发送禁用思考参数；Kimi 不发送不兼容的温度值。千问当前使用非流式回复，始终关闭可选思考；强制思考模型不保证兼容。未知兼容服务不发送专用扩展参数。

21 项自动化测试通过；已在页面切换验证全部服务商的地址和模型联动。各家的真实调用需填写对应 Key 后点击“保存模型设置”，再“测试已保存的语言模型”，尚未使用各家的真实账号逐一验收。

## 公司电脑 / BAT 浏览器版

`dist/听记君-BAT浏览器版.zip` 包含 Node.js 24.16.0 x64、生产依赖及启动 BAT。完整解压后运行 `启动听记君.bat`，打开 Edge/Chrome 使用；无需安装 Node.js。录音期间保留命令窗口和网页，无桌面置顶悬浮窗。数据默认在解压目录下 data，已有运行实例会复用其数据目录。

BAT 仍运行 node.exe，须符合 IT 许可，不保证公司策略放行。运行环境 SHA256 已与 Node.js 官方校验表核对一致。分发包不包含用户数据及密钥。

`dist/local-fix/听记君-本机连接修正版.exe` 将内嵌页面访问本地服务改为应用会话直连，避免本机流量走系统代理，不修改 Windows 代理或安全设置。此修正针对可能的代理兼容问题，不证明公司机器的 ERR_FAILED 一定由代理引起。若仍失败，先用 BAT 版确认浏览器能否访问本机地址，并将错误交给 IT 排查。

BAT 实际启动、SQLite、静态页面及依赖模块访问检查通过；21 项功能测试通过。尚未在公司电脑环境验证。
